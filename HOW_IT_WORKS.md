## Data Flow Detail

### 1. Collection Phase (Bash/obsrun)

```bash
User runs: obsrun "bwa mem ref.fa reads.fq > out.bam"

What happens inside obsrun:
┌────────────────────────────────────────────────────┐
│ 1. Capture environment                             │
│    - Get timestamp: date → "2024-01-15T10:00:00"  │
│    - Get hostname: hostname → "node42"             │
│    - Get SLURM vars: $SLURM_JOB_ID → "12345"      │
│    - Get git commit: git rev-parse HEAD            │
│                                                     │
│ 2. Write START event to .ndjson file               │
│                                                     │
│ 3. Execute user command                            │
│    bash -c 'set -euo pipefail; bwa mem ...'        │
│    │                                                │
│    └─▶ Exit code: 0 (success)                      │
│                                                     │
│ 4. Capture end metrics                             │
│    - End timestamp                                 │
│    - Calculate duration                            │
│    - Parse /usr/bin/time output (if available)     │
│                                                     │
│ 5. Write END event to .ndjson file                 │
└────────────────────────────────────────────────────┘
```

### 2. Analysis Phase (Python)

analyzer = PipelineAnalyzer([

What happens inside:

## File Format: NDJSON Explained

**NDJSON** = Newline Delimited JSON

### Regular JSON (bad for streaming):
```json
{
  "events": [
    {"type": "start", "time": "10:00"},
    {"type": "end", "time": "10:05"},
    {"type": "start", "time": "10:05"},
    {"type": "end", "time": "10:08"}
  ]
}
```
❌ Can't write until you know all events
❌ If power fails mid-way, entire file is corrupt

### NDJSON (good for streaming):
```json
{"type": "start", "time": "10:00"}
{"type": "end", "time": "10:05"}
{"type": "start", "time": "10:05"}
{"type": "end", "time": "10:08"}
```
✅ Write each event as it happens
✅ If power fails, you keep events written so far
✅ Easy to parse line-by-line with `grep`/`head`/`tail`

## The Three Ways to Use Pipewatch

### Way 1: Direct obsrun (Simplest)
```bash
obsrun "your_command"
pipewatch report pipewatch-events.ndjson -o report/
```

### Way 2: pipewatch run (More Control)
```bash
pipewatch run \
  --step-name alignment \
  --sample-id S001 \
  "bwa mem ref.fa reads.fq"
```

### Way 3: Wrap Existing Script (Best for Slurm)
```bash
# Original
sbatch run.sh

# With instrumentation
pipewatch wrap run.sh -o run_instrumented.sh
sbatch run_instrumented.sh
```

## Why Is This Better Than Manual Logging?

### Without Pipewatch:
```bash
# Your script
start=$(date +%s)
bwa mem ref.fa reads.fq > out.bam
end=$(date +%s)
echo "Alignment took $((end-start)) seconds" >> my_log.txt

# Problems:
# - Easy to forget to add logging
# - Inconsistent format between scripts
# - Hard to aggregate across 100 samples
# - No automatic resource tracking
# - Manual parsing needed for analysis
```

### With Pipewatch:
```bash
# Your script
obsrun "bwa mem ref.fa reads.fq > out.bam"

# Benefits:
# - Consistent format guaranteed
# - Automatic resource capture
# - Built-in HTML report generation
# - Cross-job aggregation
# - Standard tool everyone can use
```

## Summary

1. **obsrun** wraps your commands and writes events to a file
2. **Events** are stored as NDJSON (one event per line)
3. **pipewatch report** reads events and makes pretty HTML/JSON reports
4. **Reports** show: slowest steps, failures, memory usage, per-sample stats
5. **Works** with or without SLURM, on any Unix system

That's it! 🎉
